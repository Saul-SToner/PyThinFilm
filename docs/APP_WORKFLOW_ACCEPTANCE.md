# App 操作流程验收

2026-09-20。启动开发版 Electron、Vite 和本地后端。使用 computer-use 检查桌面窗口、案例入口、布局和高反膜图像；完整参数联动另在与 Electron 共用的本地 React 前端执行浏览器 UI 操作。不是仅调用计算 API，也不是安装包验收。

## 三条流程

| 流程 | 实际操作 | 观察结果 |
|---|---|---|
| 高反膜 → 自由设计 → 单镜 | 带入 13 层；首层改为 100 nm，探针 550→600 nm，角度 0→45° | 接收功率 0.9846→0.4425 W；说明条件跟随；2D/3D 图片使用新的请求目录且加载成功 |
| 中性分束膜 → 双支路 | 带入 4 层，首层改为 120 nm | R/T 接收从 0.3275/0.6725 W 变为 0.3611/0.6389 W；显示功率残差为 0；新图加载成功 |
| 单层减反膜 → 成像/鬼像 | MgF2、约 99.75 nm 改为 Al2O3、130 nm | 通光量 0.9457→0.8976；鬼像功率占比 0.0291%→0.1507%；文字从抑制率变为增加率，新鬼像图加载成功 |

以上数值是特定教学参数及蒙特卡洛种子下的界面读数，不是对材料优劣的一般结论。通光量是相对入射量，鬼像占比及标准误差的定义沿用 NSQ 实现报告。

## 显示与错误恢复

- Optiland 主面板、模块说明、功率/能量/鬼像/高级分析卡片初始折叠。
- 更改草稿后旧图移除并出现计算中状态；新结果带独立 URL，没有沿用旧案例图片。
- 反射/分光角度设为 75° 时明确提示仅支持 0–60°，旧图不继续显示；改回有效角度后自动重新请求。
- 案例参数较长时，开始仿真和带入按钮需要滚动到侧栏底部，当前可操作；此轮未增加固定工具栏。
- 桌面窗口及页面名称统一为 PythonFilm。

## 本轮修复

1. 初次展开 Optiland 在响应前闪出“当前不可用”：改为明确加载态。
2. 分光模块初始/重算阶段误显示“成像系统”：目录和前端初始路由都识别双支路模板。
3. 反射与分光的角度标成“视场”：改为“入射角”。
4. 通光量差值标成“相对增益”：改为“通光量变化”。
5. 75° 错误展示完整 Python 堆栈：增加中文范围检查；其它进程错误将完整诊断保存在本地 error.log，界面仅显示末行错误。
6. 窗口 HTML 与 Electron 标题仍为旧名称：改为 PythonFilm。

修复后重新核验了分光模块初始标题、加载态、中文范围错误；后端 43 项测试及前端生产构建通过。开发服务中途结束后重新启动并完成末轮复验，没有将临时连接失败计为物理模型失败。

## 收尾范围

三条代表性教学流程通过本轮交互检查。此结论不覆盖全部 40 例逐一人工操作、安装包部署、长时间稳定性或超出现有单镜/等效分光/无偏振鬼像边界的工程模型。
